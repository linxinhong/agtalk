# 图工程画布节点 · 视觉设计需求简报

> 用途：交接给视觉设计 agent 的**设计需求文档**。请先读完本简报再产出设计方案。
> 当前实现状态：agtalk 图工程 GUI（Vue 3 + Vue Flow）画布节点，功能完整但视觉一般，寻求更好设计。
> 本文档是需求与约束，不是定稿方案——设计 agent 可提出新方案。

---

## 1. 节点必须承载的信息（信息优先级从高到低）

| 信息 | 说明 | 当前呈现 | 优先级 |
|---|---|---|---|
| **生命周期状态** | pending/ready/leased/dispatched/running/verifying/succeeded/failed/blocked/timed_out/cancelled/waiting_approval | 背景色 + label 第二行 `[状态中文]` | ★★★ 最高（用户第一眼要看"进行到哪了"） |
| **认领状态** | 节点有没有 agent 在管（participant 在线=已认领；离线/无执行者=未认领） | 边框（实线绿/灰虚线）+ `!` 角标 + label `[· 认领]` | ★★★（"哪个节点没人管会卡住"） |
| **节点类型** | executor（agent 执行）/ deterministic（命令）/ join（汇聚）/ gate（分叉）/ approval（人类审批） | label 前置 emoji（🤖⚙️🔀🧭🛡️） | ★★（扫图时找"哪个是审批/分叉"） |
| **节点名（node_key）** | 作者在 spec 里声明的名字，如 `backend`、`release` | label 第一行粗体 | ★★ |
| **执行者（participant）** | 谁执行这个节点（agent 名） | 详情面板"执行者 + 在线/离线徽标" | ★（画布未显示，可选做） |
| **attempt 次数** | 第几次尝试（失败重试中的节点） | 无（详情面板有） | ★（可选：小角标 ×2） |
| **耗时** | running 节点已运行时长 | 详情面板有 | ★（可选：label 显示） |
| **失败原因** | 节点失败的具体原因 | hover title + 详情面板 | ★（hover 已够） |
| **等待人类** | waiting_approval = 需要用户行动 | 黄色 + pulse 动画 | ★★（"需要你"应抢眼） |

## 2. 视觉通道分配（当前方案：一维度一通道）

| 视觉通道 | 承载维度 | 规则 |
|---|---|---|
| **背景色** | 生命周期状态 | 蓝=进行中 / 绿=成功 / 红=失败 / 橙=阻塞 / 黄=待审批 / 灰=未开始·终止 |
| **边框 + 角标** | 认领 | 实线绿=已认领 / 灰虚线=未认领；`!` 角标=未认领警示（右上角） |
| **label emoji** | 节点类型 | 🤖执行 / ⚙️命令 / 🔀汇聚 / 🧭分叉 / 🛡️审批 |
| **hover title** | 详细描述 | 状态/执行者/认领/失败原因 多行 |
| **pulse 动画** | 活性 + 需要行动 | running/verifying 蓝呼吸；waiting_approval 黄呼吸（更快） |
| **图例** | 全部 | 右下角，状态/类型/认领 三组 |

## 3. 历史尝试与踩坑（设计时避免重蹈）

1. **自定义节点（Vue Flow `type: 'agtalk'`）不消费 `--vf-node-bg` 变量**（那是 default 节点的样式变量）→ 状态背景色全失效。若走自定义节点，颜色必须组件内部用具体 CSS 属性渲染。
2. **clip-path 形状（菱形/六边形）会裁掉节点内 label 文字**（gate 菱形/approval 六边形里放文字会被裁边）。
3. **认领双类 CSS 特异性**：`.agtalk-node.agtalk-claimed`（0,2,0）> `.agtalk-node-failed`（0,1,0）→ 曾导致认领色盖掉失败色。同类冲突需按特异性规划。
4. **SVG 头像**（djb2 生成 bot 脸）被用户否掉（效果差）；**图标库**（lucide）被评审否决（14px 小图标辨识度差、依赖收益不匹配）；**emoji** 当前在用（风格统一的 emoji 集合可用，注意 macOS 渲染差异）。
5. 右上角已被认领 `!` 角标占用——其它角标（类型/attempt）需错位或换通道。

## 4. 技术栈与约束

- Vue 3 `<script setup>` + Vue Flow（`@vue-flow/core`），CSS 变量主题（`--bg/--text/--accent`，支持深色模式）
- 节点大小约束：dagre 布局 200×56（可调）；label 两行：`<node_key>` + `[状态 · 认领]`
- 深色模式必须可读（现有配色在深色下部分文字不可见的历史问题，见 tokens.css 的 `--text-primary/secondary/tertiary`）
- 倾向：零新依赖（除非理由充分）；纯 CSS 优先
- 无障碍：颜色不能是唯一信息载体（色盲安全）——当前文字层兜底

## 5. 设计开放问题（请设计 agent 回答）

1. 节点信息密度：上述信息全上会挤，取舍建议？（哪些画布显示、哪些 hover/详情）
2. 状态 + 认领 + 类型 + 执行者 四维度的**最优通道组合**（当前：背景/边框/emoji/无）——尤其"执行者"要不要上画布（头像已否，是否有更好的轻量表达）
3. 深色模式配色方案
4. 是否值得自定义节点（在解决第 3 节踩坑 1 的前提下）以获得更好的排版（如状态进度条、attempt 角标、耗时）
5. 节点选中态、hover 态、连接点（Handle）的视觉

## 6. 验收标准

- [ ] 四种状态可一眼区分（进行中/成功/失败/待审批）且色盲安全
- [ ] 认领状态（有没有人管）不依赖颜色也能读出（文字/符号）
- [ ] 深色模式可读
- [ ] 与现有 hover title / 详情面板不重复打架
- [ ] 实现约束：Vue 3 + Vue Flow 可行；踩坑清单（§3）不重蹈
